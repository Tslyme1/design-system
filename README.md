# Дизайн-система «Уралмаш»

React-библиотека токенов, примитивов и компонентов. Собрана из измеренного разброса значений в «Проект Уралмаш» — см. [DS-AUDIT.md](DS-AUDIT.md).

Логика системы: она задаётся ограничениями, а не документацией. Невалидное значение не должно компилироваться, а не должно ловиться на ревью.

## Быстрый старт

```bash
npm install
npm run storybook  # витрина системы на 127.0.0.1:6006 — основной вход
npm run dev        # демо-страница на 127.0.0.1:5173
npm run ds:check   # линтер + сверка витрины с инвентарём
npm run typecheck  # проверка закрытости шкал
npm run build:lib  # сборка пакета в dist/
```

## Подключение в проект

```bash
npm install github:Tslyme1/design-system
```

Пакет собирается при установке — `prepare` запускает `build:lib`, поэтому
`dist/` в репозитории не лежит и не может разойтись с исходниками.

```tsx
import { Button, Stack, Table } from '@uralmash/design-system';
import '@uralmash/design-system/styles.css';
```

Стили подключаются **один раз и до собственных стилей приложения** — иначе
приложение переопределит систему случайным порядком импортов, а не осознанно.

| Что импортируется | Откуда |
|---|---|
| Компоненты, примитивы, семантические токены | `@uralmash/design-system` |
| Токены и стили компонентов вместе | `@uralmash/design-system/styles.css` |
| Только CSS-переменные тем, без компонентов | `@uralmash/design-system/tokens.css` |

Тема переключается атрибутом на корне документа — `data-theme="dark"`.
Пропа темы у компонентов нет и не будет: компонент не должен знать, в какой
теме он нарисован.

React в пакет не входит и объявлен как `peerDependency` (18 или 19).
Библиотека, принесшая с собой второй React, ломает хуки в приложении.

Публикации в npm нет: `private: true` стоит намеренно, чтобы система не уехала
в реестр раньше, чем у неё появится внешний потребитель. Когда появится —
снимается один флаг.

## Структура

```
src/
  tokens/          примитивы → семантика → CSS-переменные + обе темы
    primitives.ts    сырые значения. Импорт из компонентов запрещён
    semantic.ts      роли. Только их видит прикладной код
    tokens.css       рантайм: переменные, светлая и тёмная темы, база
    README.md        что означает каждая роль и когда её нельзя применять
  primitives/      Stack, Box, Text, Surface, Field, Icon, Grid
  components/      Button, Modal, Input, Select, Checkbox, Radio, Tag, Chip,
                   Popover, Drawer, EmptyState, AppHeader, Table, Badge,
                   Switch, Textarea, SegmentedControl, Stepper, Tooltip,
                   Skeleton, Link
  foundations/     страницы токенов для витрины. Рендерятся из самих токенов
  docs/            правила системы: выбор компонента, состояния, плотность, a11y
  playground/      демо-страница. В публичный экспорт не входит
.storybook/        конфигурация витрины, тема, общие демо-данные (fixtures)
scripts/
  ds-lint.mjs           линтер: 10 правил против обхода системы
  ds-stories-check.mjs  сверка Storybook и INVENTORY.md
  strip-css-types.mjs   чистка деклараций после сборки пакета
```

Внутри библиотеки импорты относительные, без алиаса `@/`. Алиас — удобство
сборщика, оно не переживает публикацию: tsc переносит специфаер в `.d.ts` как
написано, и у потребителя `@/primitives` не резолвится ничем. Алиасы остались
только в историях и песочнице — они в пакет не уходят.

Истории лежат рядом с компонентом (`Button.tsx` → `Button.stories.tsx`).
Story-файл пишется в том же коммите, что и компонент: компонент без историй
в системе не существует.

## Принципы

**Атомарность без частных решений.** Компонент задаёт анатомию, но ничего не знает о содержимом. `Modal` фиксирует шапку, прокручиваемое содержимое и футер — но что внутри них, решает вызывающий код.

**Токен — это запрет.** Шкала, допускающая произвольное значение, не работает как ограничение. Поэтому `gap` принимает `SpaceToken`, а не `string`: `gap="13px"` не скомпилируется.

**Два слоя токенов.** Примитивы (сырые значения) недоступны компонентам. Компоненты видят только роли. Тема переопределяет роли, и компонент о теме не знает.

**Состояния заводятся сразу.** Интерактивный элемент получает `hover`, `active`, `focus-visible` и `disabled` в момент создания. Дописанные позже состояния каждый раз получаются разными.

## Линтер

Десять правил: сырой цвет, сырые px в CSS, числа в объектах стилей, цвет строкой, импорт примитивов, фиксированная высота, сырой `z-index`, гарнитура напрямую, дефис в имени класса CSS-модуля, обращение к несуществующему классу.

Последние два — про ошибки, которые не падают, а молча ничего не делают: при `localsConvention: 'camelCaseOnly'` дефисный ключ удаляется из экспорта, а `className={undefined}` не бросает исключение — элемент просто теряет все стили. Оба раза это находил человек, поэтому теперь находит машина.

`src/tokens/` и `src/primitives/` исключены — это места, где система реализуется и обязана обращаться к значениям напрямую.

Локальное исключение — комментарий `ds-lint-disable` в строке. Каждое такое место стоит обсуждать, а не оставлять молча.

## Деплой витрины

Витрина публикуется на Vercel как статическая сборка Storybook. Настройки лежат в `vercel.json`,
в интерфейсе Vercel ничего задавать не нужно: команда сборки — `npm run build-storybook`,
каталог с результатом — `storybook-static`.

Первая настройка: `vercel.com` → **Add New… → Project** → импортировать репозиторий → **Deploy**.
Framework Preset оставить `Other` — параметры возьмутся из `vercel.json`.

Дальше каждый push в `master` пересобирает витрину, а pull request получает свой preview-адрес.

Локальная проверка того же, что соберёт Vercel:

```bash
npm ci
npm run build-storybook
npx serve storybook-static
```

Приложение «Уралмаш» — отдельный проект Vercel; его пересборку после правок в DS запускает
воркфлоу `.github/workflows/deploy-app.yml` через Deploy Hook. Витрина и приложение не связаны:
падение одного не мешает другому.

## Что дальше

Всё, что нашёл аудит, построено — 28 записей в `INVENTORY.md`. Новые компоненты не создаются без обсуждения API.

Незакрытое:

- истории 18 компонентов написаны до шаблона из 12 блоков и на него ещё не переведены — `npm run ds:stories` показывает 83 расхождения;
- у слоёв (`Popover`, `Tooltip`) нет сдвига вдоль оси: у самого края окна панель может частично выйти за границу;
- шкалы контрольных точек (breakpoints) нет — `Grid` не схлопывается по ширине, и это осознанно до первого экрана, которому это понадобится.
