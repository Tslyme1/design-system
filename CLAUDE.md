# Правила проекта

Этот файл читается при каждой задаче. Правила ниже — не рекомендации.

## Перед любой версткой

1. Прочитай `INVENTORY.md` — реестр компонентов.
2. Прочитай `src/tokens/README.md` — значения ролей токенов.
3. Открой витрину: `npm run storybook` — там видно, что уже построено.
4. Только после этого пиши код.

Если этих файлов нет — скажи об этом и не начинай верстать.

## Никогда

- Не пиши hex, `rgb()`, `hsl()`, `oklch()` вне `src/tokens/`.
- Не пиши сырые px в CSS для `padding`, `margin`, `gap`, `border-radius`, `font-size` — только `var(--space-*)`, `var(--radius-*)`, `var(--text-*)`.
- Не пиши числа в объектах стилей: `style={{ padding: 12 }}`.
- Не ставь `margin` между соседними элементами — только `<Stack gap>`.
- Не импортируй из `tokens/primitives` в компонентах — только из `@/tokens`.
- Не задавай фиксированную высоту блокам с текстом.
- Не задавай `z-index` числом — только `var(--z-*)`.
- Не задавай `font-family` напрямую — только `var(--font-heading)` / `var(--font-body)`.
- Не меняй компонент молча: правка без записи в changelog считается несделанной.
- Не создавай новый компонент, не спросив.
- Не добавляй значение в шкалу токенов, не спросив.
- Не проверяй тему внутри компонента: ни `if (theme === 'dark')`, ни отдельных пропов.

## Всегда

- Отступы — через `Stack` и `Box`.
- Типографика — через `Text variant`, никогда не `font-size` напрямую.
- Цвет — только семантические роли (`textMuted`, `surfaceRaised`), не примитивы и не ступени лестниц.
- Интерактивные элементы — сразу с `hover`, `focus-visible`, `active`, `disabled`.
- Области с данными — сразу с `loading`, `empty`, `error`.
- Новый компонент — вместе со story-файлом, **в том же коммите**. Компонент без историй в системе не существует.
- **Любое изменение компонента — запись в `src/docs/Changelog.mdx`, в том же коммите.** Не только новый компонент и удаление: новый вариант, изменённое поведение, исправленный дефект. В записи обязательна причина, а не только факт: факт через полгода виден по коду, причина не восстанавливается ниоткуда.
- Набор историй выводится из записи в инвентаре: `Варианты` → `Variants`, `Состояния` → `States`. Это проверяется машинно.
- После верстки — `npm run ds:check` (линтер + сверка витрины с инвентарём) и обновление `INVENTORY.md`.

## Когда чего-то не хватает

Остановись и спроси. Опиши:
- какую роль должен закрыть новый токен или компонент;
- какой существующий ближе всего и чем не подходит;
- что сломается, если использовать существующий.

Обход системы «на один раз» не бывает одноразовым.

## Базовые решения проекта

- **Базовая сетка:** 4px
- **Ступеней spacing:** 8 — `none, 2xs, xs, sm, md, lg, xl, 2xl` (0/2/4/8/12/16/24/32)
- **Радиусов:** 4 — `none (0)`, `sm (6)`, `md (12)`, `full`. `sm` — контролы, `md` — оболочки
- **Типографических ролей:** 8 — `caption, bodySm, body, bodyLg, label, headingSm, headingMd, headingLg` (32/24/16/16/14/12). `caption` и `bodySm` — одно значение, две роли
- **Размеры контролов:** 3 — `sm 32`, `md 40`, `lg 48`
- **Chrome (шапка сервиса):** отдельная шкала — полоса 44, ячейка 44, радиус 0
- **Ширины модалок:** 2 — `sm min(560px, 94vw)`, `lg min(1280px, 96vw)`
- **Уровней elevation:** 4 — `flat, raised, overlay, modal`. Правило: тень **или** бордер. Единственное исключение — `Modal`
- **Визуальный язык:** Geist (Vercel) — гарнитура `Geist` / `Geist Mono`, лестницы по 10 ступеней, акцент контрастом, а не оттенком
- **Темы:** светлая и тёмная, обе с первого дня
- **Платформы:** Web
- **Стек:** React 18 + TypeScript + CSS Modules + Vite
- **Источник правды для DS:** код

## Происхождение решений

Все значения выведены из `DS-AUDIT.md` — измеренного разброса в «Проект Уралмаш», и подтверждены автором. Ключевые:

- Прежняя шкала spacing (база 4px × 0.85 → 3.4/6.8/10.2…) отменена: четыре самых частотных значения не имели токена, шкалу обходили в 475 местах из 517.
- `12.5px` (72 вхождения) сведён к `12`. Пары 11/11.5, 12/12.5, 13/13.5 схлопнуты.
- Добавлены статусные роли `danger`, `success`, `warning` — раньше не было ни одной, а `var(--color-danger-700, #b3261e)` подставлял хардкод в 7 местах.
- Палитра тегов взята из приложения, а не из сторибука: версии разошлись.

Менять эти значения можно, но только осознанно и с обновлением `DS-AUDIT.md` — иначе через полгода никто не вспомнит, почему шкала именно такая.
