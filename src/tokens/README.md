# Токены

Единственный словарь значений в проекте. Всё, чего здесь нет, — не существует.

Два слоя:

- **`primitives.ts`** — сырые значения. Импортировать из компонентов **запрещено**, ловится линтером.
- **`semantic.ts`** — роли. Только их видит прикладной код, через `import { color, spacing } from '@/tokens'`.
- **`tokens.css`** — те же значения как CSS-переменные, плюс тёмная тема.

Правило `когда нельзя` в каждом разделе ниже важнее правила `когда можно`: именно оно предотвращает дрейф.

---

## Spacing

Сетка 4px, семь ступеней. Единственный способ поставить расстояние — `<Stack gap>` или `<Box padding>`.

| Токен | Значение | Когда |
|---|---|---|
| `none` | 0 | Явное схлопывание отступа — чтобы намерение читалось в коде |
| `2xs` | 2px | Зазор между иконкой и текстом внутри одного контрола |
| `xs` | 4px | Между строками одного смыслового блока |
| `sm` | 8px | Между связанными контролами (кнопки в футере, поля в строке) |
| `md` | 12px | Внутренний отступ контрола, между полями формы |
| `lg` | 16px | Внутренний отступ карточки, между блоками внутри секции |
| `xl` | 24px | Между секциями страницы |
| `2xl` | 32px | Отбивка крупных областей, вертикальные поля страницы |

**Когда нельзя:**
- Не использовать `margin` между соседними элементами — только `Stack gap`. Margin схлопывается, наследуется и не виден в структуре.
- Не подбирать ступень «на глаз, чтобы совпало» — если ни одна не подходит, это вопрос к макету, а не к шкале.
- `2xs` не для расстояния между блоками. Два блока в 2px друг от друга выглядят как ошибка рендера.

**История.** Прежняя шкала (3.4 / 6.8 / 10.2 / 13.6 / 20.4 / 27.2 — база 4px × 0.85) отменена. Четыре самых частотных значения в коде (4, 8, 12, 16) не имели токена вообще, а остальные отличались от токена на 0.2–0.8px. Итог: 475 сырых чисел против 42 обращений к токену. Шкала, которой неудобно пользоваться, не работает как ограничение.

## Radius

| Токен | Значение | Когда |
|---|---|---|
| `none` | 0 | Карточки, фигуры, таблицы, элементы шапки. **Это основа языка системы**, а не отсутствие решения |
| `md` | 4px | Интерактивные контролы: кнопки, поля, меню, модалки |
| `full` | 9999px | Только круглые объекты: аватар, номер шага, точка-индикатор |

**Когда нельзя:**
- Не скруглять карточки и фигуры. Industry рисует их как чертёжные объекты с прямыми углами — скруглённая карточка ломает язык системы целиком.
- `full` не для «слегка круглой» кнопки. Либо круг, либо `md`.

Прежние `--radius-sm` (2px) и `--radius-lg` (7px) удалены — по одному использованию каждый.

## Типографика

Токен — это **тройка** «размер + интерлиньяж + насыщенность» под именем роли. Отдельных шкал кегля и интерлиньяжа нет намеренно: в аудите они собирались заново в каждом месте и дали 18 кеглей и 8 интерлиньяжей.

| Роль | Размер / интерлиньяж / вес | Когда |
|---|---|---|
| `caption` | 12 / 1.4 / 400 | Единицы измерения, служебные подписи, заголовки колонок |
| `bodySm` | 12 / 1.4 / 400 | Плотные области: таблицы, меню, теги |
| `body` | 14 / 1.45 / 400 | Основной текст форм |
| `bodyLg` | 16 / 1.5 / 400 | Вводный текст, описания в модалках |
| `label` | 12 / 1.35 / 600 | Подпись поля, заголовок группы в меню |
| `headingSm` | 16 / 1.3 / 600 | Заголовок карточки, заголовок модалки |
| `headingMd` | 24 / 1.2 / 600 | Заголовок секции, заголовок экрана |
| `headingLg` | 32 / 1.15 / 700 | Заголовок страницы. Не больше одного на экран |

`caption` и `bodySm` — одно значение и две роли. Решение автора: размер один,
начертания оставляем. В коде обе роли ссылаются на одну тройку (`dense`
в `primitives.ts`, `--text-body-sm-*` в CSS), поэтому разъехаться они не могут:
правка размера меняет обе сразу. Роли сохранены раздельно, потому что означают
разное — если однажды служебная подпись должна будет отличаться, менять придётся
одну строку, а не искать все места употребления.

`bodyLg` и `headingSm` тоже совпадают по кеглю (16), но различаются гарнитурой
и весом: `Barlow 400` против `Barlow Condensed 600`.

Заголовки — `Barlow Condensed`, текст — `Barlow`. Переключается ролью, а не `font-family` вручную.

**Когда нельзя:**
- Никогда не задавать `font-size` напрямую — только `<Text variant>`.
- Не выбирать роль по размеру («тут нужно покрупнее»). Роль выбирается по смыслу; если смысл требует другого размера — это вопрос к шкале.
- Не использовать `headingLg` внутри карточки или модалки. Это размер заголовка страницы.

**История.** `12.5px` (72 вхождения, самый частотный размер в проекте) сведён к `12`. Пары `11/11.5`, `12/12.5`, `13/13.5` схлопнуты: разница в полпикселя не читается, но плодила по три варианта одной роли.

Шкала пересобрана автором по назначению роли: 32 страница / 24 секция / 16 карточка / 16 ввод / 14 формы / 12 плотное. Относительно первой версии выросли `body` (13 → 14), `bodyLg` (15 → 16), `headingMd` (22 → 24), `caption` (11 → 12).

## Цвет

Только семантические роли. Лестницы `100–900` живут в примитивах и в компонентах недоступны.

### Поверхности

| Роль | Когда |
|---|---|
| `bg` | Фон страницы, самый нижний слой |
| `surface` | Карточка, поле, панель — на слой выше фона |
| `surfaceRaised` | То, что лежит поверх карточки: выпадающее меню, модалка |
| `surfaceSunken` | Утопленное: заголовок таблицы, полоса шапки, фон disabled |

### Текст

| Роль | Когда |
|---|---|
| `text` | Основной текст |
| `textMuted` | Второстепенное: подписи, единицы, прочерк «—» |
| `textDisabled` | Потерявшее активность. **Не** для второстепенного — для этого есть `textMuted` |
| `textOnAccent` | Текст на акцентной заливке |
| `accentText` | Акцентный текст на светлом фоне |

### Границы

`border` — хайрлайн по умолчанию. `borderHover` — при наведении. `borderStrong` — активный или сфокусированный контрол.

### Акцент и статусы

`accent` / `accentHover` / `accentActive` / `accentSubtle` / `accentText`.
`danger`, `success`, `warning` — каждый с парой `Subtle` (слабая заливка) и `Text` (контрастная ступень для текста).

**Когда нельзя:**
- Не писать hex, `rgb()`, `hsl()` нигде, кроме `primitives.ts` и `tokens.css`.
- Не использовать `accent` как цвет абзацного текста: к фону он даёт около 3:1 — достаточно для иконок, крупного текста и элементов интерфейса, но не для текста. Для текста — `accentText`.
- Не использовать `danger` как «просто красный» для акцента. Красный в системе означает потерю данных или ошибку; декоративное применение обесценивает сигнал.
- Не брать цвет из палитры тегов для чего-либо, кроме тегов. Там цвет — пользовательский выбор, а не роль.

**История.** Статусных ролей раньше не было ни одной. В коде стояло `var(--color-danger-700, #b3261e)` в семи местах — токена не существовало, срабатывал хардкод-fallback. Код выглядел системным, не будучи им.

## Elevation

Максимум три уровня. **Правило: тень или бордер, не оба сразу.**

| Роль | Когда |
|---|---|
| `flat` | Основной вид карточек и фигур: хайрлайн-рамка, без тени |
| `raised` | Слегка приподнято, но остаётся в потоке |
| `overlay` | Выпадающее меню, поповер, подсказка |
| `modal` | Модальное окно |

**Единственное оговорённое исключение:** модалка несёт и рамку, и тень — иначе на тёмной теме её край теряется.

## Размеры контролов

`sm` 32 / `md` 40 / `lg` 48. Прежние 33/34/36/38/40 делали одно и то же в диапазоне 5px.

**Chrome — отдельная шкала:** полоса шапки 44px, ячейка 44px. Элементы шапки тянутся на всю высоту полосы, имеют нулевой радиус и разделяются хайрлайнами, а не отступами. Мерить их как кнопки формы нельзя — это разные сущности.

## Ширины модалок

`sm` — min(560px, 94vw), `lg` — min(1280px, 96vw). Было одиннадцать значений, причём `vh` и `vw` мешались в одной роли. `1280` выбран автором как чётное значение, кратное двум по половине.

## Движение

**Переходы:** `fast` 120ms / `base` 180ms / `slow` 280ms, смягчение одно — `standard` `cubic-bezier(0.2, 0, 0.2, 1)`. Это время, за которое интерфейс переходит из одного состояния в другое: появление слоя, смена фона у кнопки, раскрытие панели.

**Цикл:** `cycle` 1000ms — период оборота индикатора загрузки. Отдельная роль, а не четвёртая ступень шкалы переходов: там длительность перехода, здесь период того, что не кончается. Ступень с другим смыслом внутри одной шкалы начали бы брать для переходов, и «медленный переход» уехал бы на секунду.

Индикатор в `Button` до этого крутился на `duration.slow` — 280ms, почти четыре оборота в секунду. Это не решение, а значение, взятое за неимением другого.

**Когда нельзя:**
- Не писать длительность числом в CSS или в объекте стилей.
- При `prefers-reduced-motion: reduce` анимации сведены к 0.01ms глобально, в `tokens.css`. Компоненту об этом знать не нужно, и обходить это правило нельзя.

## Темы

Тёмная тема переопределяет **только семантику**. Лестницы 100–900 не меняются никогда.

Порядок в `tokens.css`: `:root` (светлая) → `@media (prefers-color-scheme: dark) :root:not([data-theme='light'])` (системная) → `:root[data-theme='dark']` (явный выбор, побеждает всегда).

На тёмном фоне роли берут другие ступени той же лестницы: акцент смещается с `500` на `400`, потому что `#5980a6` на тёмном не добирает контраста.

**Когда нельзя:**
- Не проверять тему внутри компонента. Ни `if (theme === 'dark')`, ни отдельных пропов. Компонент о теме не знает.
- Не переопределять примитивы в теме. Только роли.

## Расширение шкалы

Шкала расширяется только под реальный случай и только с явного согласия автора. Просьба звучит так:

1. Какую роль должен закрыть новый токен.
2. Какой существующий ближе всего и чем именно не подходит.
3. Что сломается, если использовать существующий.

Значение «на всякий случай» не добавляется никогда. Обход системы «на один раз» не бывает одноразовым.
